critical ux comp-001

Multi-monitor tiling — we only auto-tile the primary work area

Location
src/layout.rs (retile uses primary_work_area)
Source / Link
komorebi README + GlazeWM v3 README (multi-monitor support is a headline feature of both)
Description

komorebi, GlazeWM v3 and FancyZones all tile per-monitor with independent layouts. Mr. Space only auto-tiles the primary work area; pin-left/right/top/bottom correctly use the window's own monitor, but fit-all / grid / columns / rows / main-* all collapse windows onto the primary screen. Any user with 2+ monitors loses the product's core promise the moment they switch displays.

Recommended fix

Group the manageable set by monitor (MonitorFromWindow) and run tile_grid per monitor with that monitor's work area. Layout memory keys can extend to guid+monitor. Reuses the existing min-size-aware engine unchanged.
